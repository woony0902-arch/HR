# 조직구성 시뮬레이션 에이전트 — 설계 초안

## 목적
1. 전사적으로 **기능이 중복되는 조직**이 없는지 진단한다.
2. 조직 운영 관점의 **효율화(계층·스팬·인건비)** 개선안을 시나리오로 제시한다.
3. 내년 조직 개편안을 **시뮬레이션**하고 그 영향을 정량적으로 보여준다.

## 처리 단계

### 1단계 — 입력 정규화
- 조직 마스터 → 조직 트리 구축 (사업부/본부 › 담당 › 팀)
- 구성원 명단 → 조직별 현원, FTE, 직급 분포, 리더 수 집계
- 무결성 점검: 고아 조직, 소속 없는 인원, 폐지 조직 잔류 인원, 순환 참조

### 2단계 — 기능 태깅
- 각 조직의 R&R 텍스트를 기능 분류 체계(`function_taxonomy.csv`)에 매핑
- 조직 1개가 복수 기능을 가질 수 있음 → (조직, 기능, 비중) 형태로 저장
- 근거 문장을 함께 보관 (추후 설명 가능해야 함)

### 3단계 — 중복 탐지
아래 신호를 결합해 중복 후보를 점수화한다. 단일 신호로 단정하지 않는다.
| 신호 | 설명 | 필요 자료 |
|---|---|---|
| 기능 코드 일치 | 동일 기능 코드를 2개 이상 조직이 보유 | R&R, taxonomy |
| R&R 문장 유사도 | 핵심업무 문장의 의미 유사도 | R&R |
| KPI 중복 | 동일·유사 KPI 보유 | 조직별 KPI |
| 산출물 중복 | 동일 산출물을 복수 조직이 생산 | R&R, 결재 데이터 |
| 수요 조직 중복 | 같은 내부 고객을 여러 조직이 지원 | R&R |
| 시스템 Owner 중복 | 같은 시스템/데이터를 복수 조직이 소유 | IT 자산 목록 |

중복은 3가지로 구분해 판정한다. **모든 중복이 제거 대상은 아니다.**
- **진성 중복**: 같은 일을 다른 조직이 각각 수행 → 통합 후보
- **의도된 분산**: 사업부별로 동일 기능을 두는 것이 사업 특성상 타당 → 유지, 단 표준화 대상
- **경계 모호**: R&R 문구만 겹치고 실제 업무는 다름 → R&R 재정의 대상

### 4단계 — 효율 지표 산출
- 관리 계층 수(layer), 조직장 span of control 분포
- 과소 조직(예: 3인 미만 팀), 과대 조직
- 리더 비율(전체 인원 대비 보임자 수), 간접 인력 비율
- 조직별 인건비, 기능별 총 투입 인원·비용

### 5단계 — 시나리오 생성 및 비교
개편안을 조직 단위 액션의 조합으로 표현한다.
`MERGE(A,B→C)` / `SPLIT(A→B,C)` / `MOVE(A → 새 상위조직)` / `CREATE` / `ABOLISH` / `RENAME`
→ 각 시나리오에 대해 **Before/After**를 산출: 조직 수, 계층, 평균 스팬, 인건비, 기능 커버리지 결손 여부

### 6단계 — 리스크 및 실행 영향
- 기능 결손: 개편 후 담당 조직이 사라진 기능
- 제약 위반: 법정 필수 조직 미배치, 팀 최소 인원 미달
- 인적 영향: 보임 해제 인원 수, 소속 변경 인원 수
- 과거 유사 개편의 결과(이력 데이터 기반)

## 출력물
1. 진단 리포트 — 중복 후보 목록 + 근거 + 판정 구분
2. 시나리오 비교표 — 안별 Before/After 지표
3. 조직도 시각화 — 개편 전/후
4. 실행 체크리스트 — 필요한 의사결정, 협의 대상, 리스크

## 설계 원칙
- **근거 없는 결론 금지**: 모든 중복 판정에 원문 근거를 첨부한다.
- **결정은 사람이**: 에이전트는 후보와 영향을 제시하고, 통합 여부는 HR/경영진이 판단한다.
- **개인 단위 판단 배제**: 인원 개인에 대한 유지/이동 판단은 범위 밖. 조직 단위까지만.
