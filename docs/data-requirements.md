# 조직 시뮬레이션 에이전트 — 필요 자료 목록

현재 보유 자료
- 전사 구성원 명단 (소속 조직 포함)
- 각 팀 / 담당 / 본부의 역할 정리 자료

이 두 가지만으로 가능한 것은 **조직도 재현 + 문서상 R&R 문구 유사도 비교**까지입니다.
"실제로 중복인가", "합치면 얼마나 효율화되는가"를 답하려면 아래 자료가 추가로 필요합니다.
우선순위는 P0(없으면 시뮬레이션 자체가 불가) → P1(중복·효율 판정의 근거) → P2(정확도·설득력 향상) 순입니다.

---

## P0. 없으면 시뮬레이션이 돌아가지 않는 자료

### 1. 조직 마스터 (org master)
역할 정리 문서는 사람이 읽는 문서라 기계가 계층 구조를 확정할 수 없습니다.
`조직코드 / 조직명 / 상위조직코드 / 계층레벨(사업부·본부·담당·팀) / 조직장 사번 / 생성일 / 폐지일`
→ 템플릿: `templates/org_master.csv`

### 2. 구성원 상세 (명단 확장)
현재 명단에 아래 항목이 없다면 보강이 필요합니다.
`사번(익명 ID) / 소속 조직코드 / 직무(Job Family·Role) / 직급 / 입사일 / 고용형태(정규·계약·파견) / FTE / 리더 보임 여부 / 겸직 조직코드`
- **인건비**: 개인 단위 제공이 어렵다면 **직급별 평균 인건비 테이블**만 있어도 시뮬레이션 가능합니다.
→ 템플릿: `templates/members.csv`, `templates/comp_band.csv`

### 3. 조직 변경 이력 (최근 2~3년, 분기 또는 반기 스냅샷)
- 자주 신설·폐지·이관되는 조직 = 기능 정의가 불안정한 조직 = 1순위 점검 대상
- 과거 통합/분리의 결과(인원 이탈률, 재분리 여부)가 내년 시나리오의 리스크 근거가 됩니다.
→ 템플릿: `templates/org_history.csv`

### 4. R&R 문서의 정형화
보유 중인 역할 자료를 아래 필드로 쪼개 주시면 중복 탐지 정확도가 크게 올라갑니다.
`조직코드 / 미션(1문장) / 핵심업무(3~7개, 동사+목적어) / 산출물 / 의사결정 권한 / 주요 내부 고객(수요 조직)`
→ 템플릿: `templates/org_roles.csv`

## P1. "기능 중복" 판정의 근거가 되는 자료

### 5. 기능 분류 체계 (Function Taxonomy) — 사실상 이 프로젝트의 핵심
전사 공통 기능 사전(예: `재무-자금관리`, `재무-원가관리`, `IT-인프라운영`, `데이터-BI리포팅`)이 있어야
"A본부 기획팀"과 "B사업부 전략팀"을 같은 축에서 비교할 수 있습니다.
- 기존에 있으면 그대로 사용 / 없으면 에이전트가 R&R 문서에서 초안을 생성 → HR에서 확정하는 방식 권장
→ 템플릿: `templates/function_taxonomy.csv`

### 6. 업무 분장표 / 직무기술서(JD)
중복은 팀 이름이 아니라 **업무 단위(task)**에서 드러납니다.
팀 R&R보다 한 단계 아래 레벨의 분장표가 있으면 "같은 일을 4개 팀이 한다"를 증거로 보여줄 수 있습니다.

### 7. 업무 수행의 객관적 증거 (문서가 아닌 실제 행동)
R&R 문서와 실제 업무는 늘 다릅니다. 아래 중 확보 가능한 것만이라도 유용합니다.
- 전자결재: 문서 유형별 기안 부서 통계 (예: '구매요청'을 어느 부서들이 기안하는가)
- 사내 시스템/데이터 Owner 목록
- 협업툴 채널·프로젝트·Jira 프로젝트의 소유 조직
- 사규·업무규정에 명시된 담당 부서(RACI)

### 8. 비용 데이터
`조직별 인건비 / 판관비 / 외주·용역비 / Cost Center 매핑`
→ 통합안의 절감 효과를 금액으로 제시하려면 필수입니다. 최소한 인건비만이라도.

### 9. 조직별 KPI / 성과지표 목록
**동일하거나 유사한 KPI를 여러 조직이 보유** = 중복의 강력한 신호입니다.
→ 템플릿: `templates/org_kpi.csv`

### 10. 내년 인력 운영 계획
`승인 정원(TO) / 현원 / 채용 진행 중 포지션 / 예정된 퇴직·전환배치`
→ 시뮬레이션 결과를 실행 가능한 숫자로 만들어 줍니다.

## P2. 정확도와 설득력을 크게 높이는 자료

### 11. 협업 네트워크 데이터 (Organizational Network Analysis)
메일·회의·결재라인·프로젝트 참여 이력의 **집계 메타데이터**(본문 제외)로
"조직 경계가 실제 협업 밀도와 맞는가"를 검증합니다.
- 조직 간 상호작용이 극단적으로 높으면 → 통합 후보
- 같은 조직 내부인데 상호작용이 없으면 → 분리 후보
- **개인정보 이슈**: 반드시 조직 단위 집계값으로만 수령 (개인 식별 불가 형태)

### 12. 생산성 / 운영 지표
팀별 처리 건수, SLA, 인당 매출, 인당 관리 자산 등. 효율화 논의의 분모가 됩니다.

### 13. 조직 건강도
조직별 퇴사율, 조직몰입도 서베이 결과, 리더 span of control 현황, 관리 계층 수(layer).
→ "중복 제거"가 아니라 "과도한 계층 축소"로 효율이 나오는 경우가 많습니다.

### 14. 내년 사업계획 / 전략 과제
조직은 전략을 따릅니다. 신설·강화·축소 판단의 최상위 근거이며,
이것이 없으면 에이전트는 "현재 구조의 정리"만 할 수 있고 "내년을 위한 설계"는 못 합니다.

### 15. 제약 조건 목록
- 법·규제상 필수 조직 (준법감시, 안전보건, 정보보호 등)
- 노사 협의 대상 사항
- 인사 규정상 팀 최소 인원, 조직장 직급 요건
→ 에이전트가 실행 불가능한 안을 내는 것을 막습니다.
→ 템플릿: `templates/constraints.csv`

### 16. 외부 벤치마크
동종업계 조직 구조, 기능별 적정 인력 비율(예: HR 1인당 직원 수, IT 인력 비중).
내부 데이터만으로는 "많다/적다"의 기준이 없습니다.

## 우선 확보 권장 3종
시간이 제한적이라면 이 순서로 요청하시길 권합니다.
1. **조직 마스터 + 구성원 상세** (P0-1, P0-2) — 시뮬레이션 엔진의 최소 입력
2. **조직별 KPI 목록** (P1-9) — 가장 적은 비용으로 중복 신호를 가장 많이 주는 자료
3. **조직별 인건비/비용** (P1-8) — 효율화 효과를 금액으로 환산

## 개인정보 취급 원칙
- 사번은 해시 또는 일련번호로 치환하여 반입 (이름·연락처 불필요)
- 인건비는 개인값 대신 직급·직무별 밴드 사용
- 협업 네트워크는 조직 단위 집계값만 사용
- 평가등급, 징계 이력 등 민감 정보는 이 시뮬레이션에 불필요
