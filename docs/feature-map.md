# 기능 구조 — 두 페이지, 하나의 엔진

원칙: **계산은 즉시(모델 없이), 해설은 대화로, 기록은 폼으로.**
깐깐한 임원에게 30초 기다림 없이 숫자를 먼저 보여주고, 모델은 해설과 "받을 질문"에만 쓴다.

```
                 ┌──────────────────────────┐   ┌──────────────────────────────┐
                 │ A. 조직 진단 대시보드         │   │ B. 조직 시뮬레이션 에이전트         │
                 │    훑어본다 · 모델 없음        │ ⇄ │    묻고 · 돌리고 · 기록한다          │
                 └──────────────────────────┘   └──────────────────────────────┘
                              ▲                              ▲
                              └───────── data.json ──────────┘   팀 단위 집계 · 개인 행 없음
                              └───────── db (원장) ──────────┘   판정 · 지침, 두 페이지가 함께 읽음
```

## A. 조직 진단 대시보드 — 보기

| 구역 | 내용 | 답하는 질문 |
|---|---|---|
| 요약 | 인원·팀·직책자 비율·평균 연령·50세 이상·5년 내 정년, 2024 대비 | 지금 어디에 서 있나 |
| 3개년 추이 | 인원·평균 연령·50세 이상 %·5년 내 정년 | 어디로 가고 있나 |
| 인력 구조 | 연령대 분포, 연도별 정년 도래, 정년 집중 조직 | 정년 절벽은 언제 어디서 오나 |
| 조직 구조 | 본부별 팀·인원·팀당 인원·소규모 팀·직책자 비율 | 본부 간 편차는 |
| 조직 계보 | 판정 신뢰도(5단계) 분포, 검토 필요 목록 | 이력을 믿어도 되나, 사람이 봐야 할 건 |
| 기능 | 기능 지도, 병렬 조직군, 중복 후보 + 판정 상태 | 같은 일을 몇 곳이 하나 |
| 미션 정합성 | 담당 커버율, 선언했으나 맡은 팀 없는 항목 | 선언과 실제가 맞나 |
| 지역 | 기능별 권역 분포, 권역별 현황 | 이 기능을 전국 몇 개 단위로 |
| 전제 | 지침 원장, 판정 원장 (실시간) | 모든 판단의 전제는 |

필터 하나(본부)가 팀 단위 구역 전체를 좁힌다. 모든 차트에 **표로 보기**가 있다.

## B. 조직 시뮬레이션 에이전트 — 메뉴 8개

| # | 메뉴 | 작업판 (즉시) | 대화 (모델) | 도구 |
|---|---|---|---|---|
| **보기** | | | | |
| 1 | 조직 찾기 | 이름 검색 → 현황 카드(인원·연령·R&R·3개년 이력·판정) | 해설, R&R 연도별 비교 | resolve_org · team_profile · rr_history · org_overview · lineage_review · workforce_risk |
| 2 | R&R 검색 | 키워드·연도 → 소관 조직과 문맥 | 왜 나뉘어 있는지 대조 | search_rr · resolve_org · team_profile · rr_history |
| **돌려보기** | | | | |
| 3 | 시뮬레이션 | 개편안 조립(통합·폐지) → **실행** → Before→After·연령·지역·제약 | 해설 + "받을 질문", "왜 그 숫자야?" | resolve_org · edit_scenario · run_simulation · recall_ledger · region_view · workforce_risk |
| **판정하기** | | | | |
| 4 | 계보 검토 | 검토 필요 큐 → 판정 폼 | 근거 대조 | lineage_review · rr_history · record_entry |
| 5 | 중복 판정 | 미판정 후보 → 판정 폼 | 두 팀 R&R 대조 | duplicate_candidates · rr_history · parallel_families · record_entry |
| **기록하기** | | | | |
| 6 | 지침 관리 | 지침 폼(출처·구분·효력·전달·규칙), 미확인 목록 | 말로 하면 구조화해 확인 | record_entry · recall_ledger |
| 7 | 원장 | 판정·지침 전체 조회·검색 | 요약 | recall_ledger |
| 8 | 자유 질문 | 전사 한눈에 | 모든 도구 | 전부 |

메뉴를 고르면 세 가지가 바뀐다: **작업판**, **대화에 넘기는 도구 집합**(적을수록 빠르고 싸다), **모델에 주는 메뉴 지시**.
작업판에서 실행한 시뮬레이션 결과는 모델에게 넘어가므로 "방금 돌린 결과를 해설해줘"가 된다.

## 원장 — 두 페이지의 공통 전제

| | 판정 원장 | 지침 원장 |
|---|---|---|
| 담는 것 | 이 조직에 대해 이렇게 판단했다 | 모든 판단은 이 전제 위에서 |
| 쓰는 곳 | 에이전트 4·5·8 (폼 또는 대화) | 에이전트 6·8 |
| 읽는 곳 | 시뮬레이션 경고, 중복 후보 필터, 대시보드 | 시뮬레이션 제약 검사, 해설 우선순위, 대시보드 |
| 저장 | 공유 저장소(db). 없으면 브라우저 | 같음 |

## 하지 않는 것
개인 평가·배치, 개인 명단의 모델 전달, 원장의 자동 기록(사람 확인 없이), 최종 승인.


## 기준값의 우선순위 (2026-09 추가)

시뮬레이션이 검사하는 기준값(최소 인원·최대 관리 폭·과대 팀·직책자 비율 상한·보호 조직)은 세 층에서 온다.

| 층 | 어디서 | 남는가 |
|---|---|---|
| config | `config/columns.yaml` params | 코드와 함께 |
| 지침 | 원장의 규칙 지침 (강제 > 권고, 철회·만료 제외) | 원장에 영구 |
| 가정(대화) | 대화창에서 말한 조건 → `set_assumptions`, 또는 작업판 '이번 시뮬레이션의 기준' 카드 | 이 대화에서만. 초기화하면 사라짐. '지침으로 저장'으로 원장에 올릴 수 있음 |

뒤 층이 앞 층을 덮는다. 결과의 `적용기준` 표와 제약 위반 문구에 출처가 붙는다. 특정 지침을 이번만 빼는 것(`ignore_directives`)과 수치가 아닌 전제(`note`)도 가정으로 넣을 수 있다.
