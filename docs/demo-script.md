# 실장님 시연 대본 — 에이전트 v0

## 실장님 성향에 맞춘 원칙
실장님은 **조직 시뮬레이션에 기대가 크고, 깐깐하고 논리적**이다. 그래서

1. **시뮬레이션이 주인공이다.** 25분 중 12분을 여기에 쓴다. 탐색 기능은 짧게 지나간다.
2. **모든 숫자에 출처가 붙는다.** "왜 그 숫자냐"가 나오면 에이전트가 `계산근거`를 그대로 옮긴다. 시연자가 대신 설명하지 않는다 — 도구가 답하는 것을 보여주는 것이 목적이다.
3. **단정하지 않는 것을 약점으로 보이게 하지 않는다.** "판단하지 않는다"가 아니라 "판단에 필요한 것을 빠짐없이 내놓는다"로 말한다. 시뮬레이션 끝에 붙는 **"이 안이 받을 질문"**이 그 증거다.
4. **틀린 가정을 실장님이 잡아내면 그것이 성공이다.** 그 자리에서 지침·판정으로 기록되는 것을 보여준다. 이 도구는 실장님의 판단을 대체하는 것이 아니라 축적하는 것이다.

## 준비
```bash
export ANTHROPIC_API_KEY=...
python3 agent.py                  # 실제 데이터 (보안 확인 후)
python3 agent.py --data data_demo --ledger data_demo/ledger/decisions.csv   # 합성 데이터 (보안 확인 전)
```
- 보안 확인 전이면 합성 데이터로 **행동**을 보여주고, 실제 데이터 결과는 `output/01_진단리포트.md` 로 따로 보여준다.
- 첫 화면에 "이렇게 물어보세요" 예시가 뜬다. 실장님이 직접 타이핑하시게 한다. `?` 로 도움말.
- 시연 전 혼자 한 번 돌려 대화 루프를 검증한다 (이 코드는 API 키가 없는 환경에서 작성되어 실제 호출 검증이 아직 없다).

## 시연 순서 (25분)

### 1. 검색 — "이 업무는 어느 팀 소관인가" (2분)
> **질문>** 해지방어는 어느 팀이 해?

기대: 2026년 R&R에서 4개 팀(리텐션팀·대전영업팀·천안영업팀·월정액리텐션팀)을 문맥과 함께 보여준다.
**보여줄 것**: R&R 문서를 뒤지지 않아도 된다. 팀장님 대시보드의 검색과 같은 기능이 대화 안에 있다.
**실장님이 물을 것**: "2024년에는?" → `연도`를 바꿔 다시 찾는다. 기능이 어디서 어디로 옮겨갔는지가 보인다.

### 2. 되묻기 — 조직명을 지어내지 않는다 (2분)
> **질문>** 구축팀 상황 알려줘

기대: 6개 후보(수남·수북·대구·부산·서부·중부)를 나열하고 어느 것인지 되묻는다.
**보여줄 것**: 모델이 조직을 추측하지 않는 구조. `인사기획팀`처럼 없는 이름을 넣으면 없다고 하고 비슷한 조직을 제안한다.

### 3. 현황 — 계산·가정·판단의 분리 (3분)
> **질문>** 대구구축팀 현황

기대: 인원 12·평균연령 53.2·5년 내 정년·R&R·3개년 이력(수도권2구축팀 등 승계 근거)을 말하고,
**"지역은 조직명에서 추론"**, **"이력은 구성원 이동으로 추정"**이라는 가정을 붙인다.
**실장님이 물을 것**: "이력은 어떻게 알아냈나" → 부서코드는 재사용되어 쓸 수 없고 사람의 이동으로 추정했다는 답이 나온다. 이 답이 나오는지가 중요하다.

### 4. 시뮬레이션 — 주인공 (12분)
> **질문>** 대구랑 부산 구축팀을 합치면 어떻게 돼?

기대 (Before → After 표):
- 팀 −1, 직책자 −1, 소속 변경 27명, 보임 해제 1명(명단은 로컬 파일로만)
- 만들어진 조직: 27명 · 평균연령 52.7 · 50세 이상 26명 · **5년 내 정년 7명 (26%)**
- **지역 간 통합 경고**: 대구 + 부산 — 사람은 원래 자리에 남는다
- 제약 위반: span 26명 (기준 15명 · GRP-02) — 출처가 지침 id로 붙는다
- 끝에 **"이 안이 받을 질문"**: 팀장 1명이 두 국사 26명을 관리할 수 있는가 / 5년 뒤 20명이 되는 조직을 지금 만드는 이유는

> **질문>** 거기에 서부구축팀도 넣어봐

기대: 개편안이 **덧붙여진다**(초기화되지 않는다). 지역 3곳, 인원 39명, 정년율이 다시 계산된다.
**보여줄 것**: 대화하듯 안을 쌓아 가며 매번 전체 영향을 다시 본다.

> **질문>** 왜 보임 해제가 1명이야?

기대: `계산근거`를 그대로 옮긴다 — "통합 대상 팀장 중 1명(keep_leader 또는 최장 근속)을 제외한 나머지".
**보여줄 것**: 숫자의 근거를 도구가 직접 답한다. 이 순간이 깐깐한 임원에게 가장 중요하다.

> **질문>** 정년 대응이 목적이면 이 안이 맞는 거야?

기대: 판단하지 않는다. 대신 "정년 대응이 목적이면 봐야 할 지표는 통합 조직의 5년 내 정년율이고, 이 안은 26%다. 정년이 몰린 조직끼리 합치면 문제가 해소되는 것이 아니라 이연된다"를 계산으로 말하고, 판단은 실장님께 돌린다.
**실장님 반응을 기록한다** — 여기서 "판단이 답답하다"가 나오면 그것이 가장 중요한 피드백이다.

### 5. 판정 원장 — 판단을 건져 올린다 (3분)
> **질문>** 구축팀은 국사 때문에 합칠 수 없어. 그대로 둬야 해.

기대: "이렇게 기록할까요? 대상 구축팀 군 / 판정 유지 / 사유 국사 위치로 인력 집중 불가 / 판정자 HR실장"이라고 **확인을 먼저 구한다.** 동의하면 기록.
이후 같은 통합안을 시도하면 `add_action` 단계에서 기존 판정을 먼저 알린다.
**보여줄 것**: 내년에 같은 논쟁을 반복하지 않는 장치. 실장님의 판단이 도구의 전제가 된다.

### 6. 지침 원장 — 임원만 아는 전제 (2분)
> **질문>** 그룹에서 올해 팀장 자리는 늘리지 말라고 구두로 내려왔어

기대: 출처(그룹·구두), 규칙인지 방향인지, 검사 조건이 있는지 묻고 구조화해서 확인을 구한다. 기록되면 **미확인** 상태.
**보여줄 것**: 지금까지 임원 머릿속에만 있던 전제가 처음으로 기록되어 시뮬레이션의 제약이 된다.

### 7. 범위 밖 (1분)
> **질문>** 그 팀 팀장 누가 제일 나아?

기대: 개인 평가는 범위 밖이라고 답한다.

## 피드백 질문 — 이 순서로

1. **시뮬레이션 결과에서 빠진 지표가 있는가?** 실장님이 개편안을 볼 때 항상 보는 숫자 중 없는 것.
2. **"이 안이 받을 질문"이 실제로 실장님이 던질 질문과 일치했는가?** 안 맞는 것이 있으면 그것이 곧 지침 원장에 들어갈 내용이다.
3. **가정을 매번 붙이는 것이 도움이 되는가, 소음인가?** 한 번만 말하면 되는 가정은 무엇인가?
4. **"판단하지 않는다"가 답답했는가?** 어느 지점에서는 도구의 의견을 듣고 싶었는가?
5. **되묻는 빈도가 적절한가?**
6. **첫 화면 예시 질문 중 실장님이 실제로 쓸 것 같은 것은?** 없는 것은 무엇인가?
7. **판정 원장의 판정자 이름** — 기록의 주체를 누구로 할 것인가?
8. **기능 분류 사전 확정 세션**을 잡을 수 있는가? (기능 지도 수치는 사전이 시드라 아직 과다 집계)
9. **팀장님 대시보드와의 역할 분담** — 훑어보기는 대시보드, 묻고 돌려보고 기록하기는 에이전트로 나누는 것에 동의하는가?

## 시연에서 솔직하게 말할 것
- 기능 지도의 수치는 사전이 시드라 과다 집계되어 있다 (예: 안전환경 37팀). 확정 세션이 필요하다.
- 지역은 조직명에서 추론한 것이다. 근무지 데이터가 오면 교체한다.
- 승계 이력은 구성원 이동으로 추정한 것이다. 확인이 필요한 84건은 사람이 봐야 한다.
- 대화 루프는 API 키가 없는 환경에서 작성되어 첫 시연 전에 검증이 필요하다.
- 배포 환경(외부 LLM 전송)은 미정이며, 그래서 개인 데이터가 모델에 닿지 못하게 코드로 막아 두었다.
