# 팀장님 대시보드와 에이전트 — 무엇을 가져오고 어떻게 합치나

## 두 도구는 근거가 다르다

| | 조직·R&R 변천 대시보드 (팀장님) | 조직 설계 에이전트 |
|---|---|---|
| 데이터 | 3개년 R&R 문서 + 보임도 | 3개년 구성원 명단 + R&R + 보임도 |
| 승계 판정 근거 | R&R 본문 · 조직명 · 조직장 · 상위 조직 | **구성원 이동** · 조직명 · 조직장 |
| 성격 | 보기(read) — 탐색·검색·비교 | 계산·시뮬레이션·기록 |
| 강점 | 문서 원문에 즉시 닿는다. 검토 필요 큐가 있다 | 인원·연령·정년·span, 개편 시뮬레이션, 판정·지침 원장 |
| 없는 것 | 인원 수, 연령, 시뮬레이션, 판정 기록 | R&R 전문 검색, 연도별 나란히 비교 (→ 이번에 추가) |

**같은 조직의 승계를 서로 다른 근거로 판정하고 있다.** 합치면 근거가 5개가 된다.
근거가 모두 맞으면 확정, 어긋나면 사람이 본다. 이것이 통합의 핵심이다.

## 대시보드에서 가져온 것 (구현 완료)

| 대시보드 기능 | 에이전트 도구 | 비고 |
|---|---|---|
| R&R 검색 — "이 업무는 어느 조직 소관인가" | `search_rr(query, year)` | 세션 중 가장 자주 쓰일 질문 |
| 조직 탐색 — 연도별 미션·R&R 전문 | `rr_history(team)` | 3개년 나란히 + 전년 대비 변경폭 |
| 승계 경로 — 판정 + 신뢰도 + 검토 필요 큐 | `lineage_review()` | 구성원 이동·조직명·조직장 3근거 결합. 확정/높음/보통/낮음/확인필요 |
| R&R 변경 — 변경폭 순 정렬 | `rr_history` 의 변경폭 + 진단 리포트의 R&R 궤적 | |

실제 데이터 결과: 승계 판정 569건 중 확정·높음 407건, **사람 확인 필요 84건**
(대시보드는 108개 계보를 검토 필요로 표시 — 근거를 합치면 줄어든다).

## 가져오지 않은 것과 이유

- **보임 현황의 성명 표시** — 대시보드는 끝자를 가려 표시하지만 에이전트는 이름을 전혀 다루지 않는다. 겸직·교체는 사번 기준 집계로만.
- **화면 자체** — 에이전트는 대화형이다. 표·트리·차트가 필요한 탐색은 대시보드가 낫다.
  두 도구를 경쟁시키지 말고 **역할을 나눈다**: 훑어보기는 대시보드, 묻고 돌려보고 기록하기는 에이전트.

## 합치는 방법 — 승계 판정을 한 곳에 둔다

1. 대시보드의 승계 경로를 CSV로 내보낸다 (탭에 '저장' 버튼이 있다)
2. 에이전트가 그 판정을 **네 번째·다섯 번째 근거**로 읽는다 (R&R 본문 유사도, 상위 조직)
3. 두 도구의 판정이 어긋나는 건 → 검토 큐 → 세션에서 사람이 확인 → **판정 원장(kind=구조)** 에 기록
4. 확정된 승계 계보 파일 하나를 두 도구가 함께 읽는다

이렇게 되면 "이 팀은 저 팀의 후신이다"가 두 사람의 두 도구가 아니라 **한 회사의 한 기록**이 된다.
그 위에서야 개명된 조직의 이탈률·R&R 궤적·정년 추이가 끊기지 않고 이어진다.
