# 조직을 구성해야 하는 임원에게 필요한 에이전트

## HR과 임원은 같은 조직도를 다른 질문으로 본다

| | HR 실장 | 본부장·센터장 |
|---|---|---|
| 관점 | 전사 | 내 본부 |
| 묻는 것 | 어디가 중복인가, 공정한가, 규정에 맞나 | 내 미션을 이 구조로 할 수 있나 |
| 가장 민감한 것 | 형평성, 절차 | **내 보임자가 어떻게 되나** |
| 최종 산출물 | 전사 개편안 | 상신 자료 — 왜 이렇게 설계했는지 |
| 두려워하는 것 | 근거 없는 결정 | **상신했다가 되돌아오는 것** |

임원은 정답을 원하지 않는다. **자기 안이 어디서 공격받을지** 미리 알고 싶어 한다.
그래서 임원용 에이전트는 "설계 조력자"이자 **"상신 전 레드팀"** 이어야 한다.

---

## 이 회사 임원이 처한 상황 (데이터 기준)

- 2년 연속 대규모 개편: 2025년 48%, 2026년 56%가 소속을 옮겼다. CP/CO → 사업부 → 본부로 구조 자체가 두 번 바뀌었다.
- 보임 자리가 줄고 있다: 302 → 271 → 246명. 임원 개편은 곧 **자기 사람의 자리** 문제다.
- 본부 인원의 절반이 50세 이상이고, 신규 채용은 사실상 멈췄다(2026년 16명).
- 전국 국사 구조라 지역 조직은 물리적으로 묶여 있다. 합쳐도 사람은 못 움직인다.
- 2026년 CEO가 바뀌었다. 상신의 기준선이 달라졌을 가능성이 높다.

이 상황에서 임원이 실제로 답해야 하는 질문은 "중복이 있나"가 아니다.

---

## 임원이 실제로 던지는 일곱 가지 질문

### 1. "내년에 내 본부에서 누가 빠지고, 그러면 어느 기능이 비나"
정년·이탈을 본부 단위로 시뮬레이션해 **기능별 결손 시점**을 보여준다.
"2028년에 구축 기능 담당자 7명 중 4명이 정년" — 개편의 출발점은 여기다.

### 2. "이 담당을 없애면 담당장은 어디로 가나"
개편안의 보임 영향을 **사람 단위로** 보여준다. HR용에서는 건수만 보이지만,
임원은 자기 본부 안에서 이 명단을 봐야 설계를 할 수 있다.
(경계: 자기 본부 안에서만. 옆 본부 명단은 보이지 않는다.)

### 3. "본부 미션과 팀 R&R이 맞물려 있나"
3개년 담당급 R&R이 확보되어 이제 가능해진 분석이다.
본부 미션 → 담당 R&R → 팀 R&R로 내려가며 **끊긴 곳**(미션에는 있는데 아무 팀도 안 하는 것,
팀은 하는데 미션에는 없는 것)을 찾는다.

### 4. "옆 본부와 겹치는 게 뭔가 — 내가 넘겨야 하나, 받아야 하나"
경계 협상용이다. 자기 본부와 인접 본부 사이의 기능 중복·인원 이동 이력을 보여준다.
"작년에 소싱팀이 A사업부에서 우리 쪽으로 왔는데, 구매팀과 같은 일을 하고 있다."

### 5. "내 설계안이 전사 기준을 위반하나"
상신 전 사전 검증. 팀 최소 인원, span 상한, 법정 필수 조직, 그리고
**HR이 이미 '유지'로 판정한 조직을 건드리고 있는지** — 판정 원장을 임원도 조회한다.

### 6. "이 안을 어떻게 설명하나"
상신 자료 초안: 설계 근거(데이터), 영향(인원·보임·기능), 리스크, 대안과의 비교.
임원이 쓰는 문서지만 HR이 검토할 것을 전제로, HR이 물을 질문에 미리 답한다.

### 7. "내가 놓친 게 뭔가"
에이전트가 먼저 묻는다.
"이 담당을 폐지하면 안전보건 기능 담당자가 본부에 없어집니다. 의도한 것입니까?"
"통합 후 팀장 1명이 대구·부산 26명을 관리합니다. 국사가 두 곳입니다."

## HR용과 무엇이 같고 무엇이 다른가

### 같은 것 — 엔진
도구 계층(구조·동역학·인력·기능·지역·명명·시뮬레이션), 판정 원장, 데이터 경계는 하나다.
따로 만들면 HR과 임원이 **다른 숫자**를 들고 만난다. 그게 최악이다.

### 다른 것 — 렌즈와 권한

| | HR 뷰 | 임원 뷰 |
|---|---|---|
| 기본 범위 | 전사 | 자기 본부 (+ 인접 본부는 집계만) |
| 개인 명단 | 로컬 파일로만, 모델은 건수만 | 자기 본부 보임자는 세션에서 조회 가능 (모델 미전달은 동일) |
| 첫 화면 | 중복 후보·불안정 조직 | **내 본부의 정년 절벽·미션 정합성** |
| 시뮬레이션 초점 | 전사 델타 | 내 본부 델타 + 옆 본부에 미치는 영향 |
| 판정 원장 | 기록·철회 권한 | 조회 + **설계 근거 기록** (판정은 HR 몫) |
| 산출물 | 진단 리포트 | 상신 자료 초안 |

### 판정 원장은 양방향이어야 한다
- HR의 판정("지역 구축팀은 유지")을 임원이 보고 설계에 반영한다
- 임원의 설계 근거("DC기술담당 통합은 AI DC 확장 대응")를 HR이 보고 전사 정합성을 검토한다
- 같은 원장에 **기록 주체를 구분**해 남긴다. 누가 왜 그렇게 했는지가 내년의 자산이다.

## 임원용 세션의 흐름

```
1. 현황     "내 본부 지금 상태" — 인원·연령·보임·미션 정합성 한 장
2. 절벽     "손대지 않으면 3년 뒤" — 기능별 결손 시점
3. 설계     "이렇게 바꾸면" — 누적 편집 시뮬레이션
4. 레드팀   "이 안의 약점" — 기준 위반, 옆 본부 충돌, HR 기존 판정, 놓친 기능
5. 상신     "설명 자료" — 근거·영향·리스크·대안 비교
```

4번이 임원용의 핵심이다. HR용에서는 "판정 필요"로 끝나는 지점이,
임원용에서는 "**HR이 이렇게 물을 것입니다**"로 바뀐다.

---

## 하지 않는 것 — 임원용에서 특히 중요

- **개인 평가·역량 판단** — "누가 팀장감인가"에 답하지 않는다. 연령·직책·근속만 본다.
- **옆 본부 개인 명단 열람** — 경계 협상은 집계 수준에서만.
- **HR 판정의 우회** — 원장의 '유지' 판정을 임원 세션에서 뒤집을 수 없다. 이의는 기록으로 남긴다.
- **상신 자료의 자동 제출** — 초안까지. 문서의 주체는 임원이다.

이 경계는 임원을 제약하는 것이 아니라 **보호하는 것**이다.
"에이전트가 그렇게 하라고 했다"는 말이 나오면 안 된다.

## 새로 확보된 자료가 여는 것

| 자료 | 열리는 분석 |
|---|---|
| 3개년 담당·본부급 R&R | **미션 정합성** (본부 → 담당 → 팀 연결 검증), 상위 R&R의 3년 변천 |
| 3개년 팀 R&R | 팀 R&R 궤적 — 기능이 어디서 어디로 옮겨 다녔는지 |
| 3개년 보임도 | 보임자 이동·교체 이력, 보임 자리 축소 추세(302→271→246) |
| 3개년 보임 조직도 | 상위 구조 변천의 시각 자료 |

**취급 주의**: 보임도와 조직도에는 **실명**이 있다(社內秘 표기). 지금까지 자료는 사번뿐이었다.
ingest 단계에서 성명 컬럼을 제거하고, 저장소·모델·리포트 어디에도 싣지 않는다.
