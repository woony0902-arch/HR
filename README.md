# 조직구성 시뮬레이션 에이전트

내년 전사 조직 개편을 지원하는 진단 · 시뮬레이션 도구입니다.

**목표**
1. 전사 기능 중복 조직 진단
2. 조직 운영 효율화(계층·span·조직 안정성) 개선안 도출
3. 개편 시나리오의 Before → After 시뮬레이션

**조직 계층**: 본부/사업부 › 담당 › 팀

---

## 빠른 시작

```bash
pip install -r requirements.txt

python3 scripts/make_sample_data.py      # 합성 데이터 생성 (실제 자료 없이 검증용)
python3 run.py diagnose                  # 1차 진단 리포트
python3 run.py simulate plans/*.yaml     # 개편 시나리오 시뮬레이션
```

산출물은 `output/` 에 생성됩니다.
- `01_진단리포트.md` — 구조·동역학·인력·기능 중복 진단
- `02_시뮬레이션리포트.md` — 시나리오별 Before→After
- `tables/*.csv` — 모든 분석 결과의 원본 테이블

## 실제 데이터 연결

1. `data/` 에 아래 파일을 넣습니다.
   - `members_2024.csv`, `members_2025.csv`, `members_2026.csv` — 연도별 구성원 명단
   - `team_roles.csv` — 팀별 역할 정의표
2. `config/columns.yaml` 의 **우측 한글 컬럼명**을 실제 파일 헤더에 맞춰 수정합니다.
3. `config/columns.yaml` 의 `positions` 에 실제 직책 표기를 반영합니다(팀장·담당임원·본부장).
4. `python3 run.py diagnose` 를 실행하고, 리포트 0장(데이터 품질 점검)을 먼저 확인합니다.

### 입력 스키마

**구성원 명단** (연도별 1개 파일)

| 컬럼 | 필수 | 비고 |
|---|---|---|
| 사번 | ✅ | 연도 간 동일해야 이동·이탈 추적 가능 |
| 본부코드 / 본부명 | ✅ | |
| 담당코드 / 담당명 | ✅ | |
| 팀코드 / 팀명 | ✅ | 코드가 있어야 개명과 신설을 구분 |
| 입사일 | ✅ | 근속 산출 |
| 나이 | ⬜ | 없으면 연령·승계·정년 분석 제외 |
| 성별 | ⬜ | 다양성 현황 참고용 |
| 직책 | ✅ | span of control, 보임 영향 산출 |

**팀 역할 정의표**: `팀코드, 팀명, 역할` (역할 1건당 1행, 또는 한 셀에 줄바꿈으로 나열)

## 무엇이 계산되는가

### 진단 (`run.py diagnose`)

| 영역 | 산출물 |
|---|---|
| 데이터 품질 | 사번 중복·공백, 조직코드 불일치, 팀장 공석, 나이·입사일 모순, 스냅샷 기준일 이상 |
| 구조 | 계층, span of control 분포, 소규모/과대 팀, 직책자 비율, 본부별 비교 |
| 동역학 (3개년) | 조직 신설·폐지·개명·이관 이력, 불안정 조직 점수, 조직 간 인원 이동, 조직별 이탈률 |
| 인력 구조 | 연령·근속 분포, 승계 리스크, 정년 도래 추이, 자연감소 시뮬레이션 |
| 기능 중복 | 전사 기능 지도, 팀 쌍 중복 후보(판정 초안 포함), 담당 조직 없는 기능 |

### 시뮬레이션 (`run.py simulate`)

개편안을 `MERGE / SPLIT / MOVE / ABOLISH / CREATE / RENAME` 조합으로 기술하면:

- **구조 델타** — 조직 수, 계층, span, 평균 팀 규모, 직책자 수
- **사람 영향** — 소속 변경 인원, 본부 이동, **보임 해제 인원(명단 포함)**, 신규 팀장 필요, 미배치
- **기능 커버리지** — 담당 조직이 사라지는 기능(결손), 잔존 중복, 하나로 모인 기능
- **제약 위반** — 최소 인원, span 상한, 팀장 공석 (개편으로 **새로 생긴 것**과 기존 문제를 구분)

시나리오 작성 예시는 `plans/A_보수안.yaml` 참조.

## 이 도구의 한계

현재 입력으로는 **개편이 무엇을 바꾸는지**까지 계산됩니다.
**개편이 좋은지**는 판단 기준이 데이터에 없으므로 판정하지 않습니다.

| 하려면 필요한 자료 | 열리는 기능 |
|---|---|
| 조직별 KPI | 중복 후보의 실증, R&R–KPI 정합성(선언만 되고 안 돌아가는 기능) |
| 조직별 인건비 | 개편안의 금액 환산 |
| 내년 전략과제 | 신설·강화 기능 도출, 전략 정합성 검증 |

또한 중복 판정의 `판정초안`은 **참고용**입니다.
진성 중복인지 의도된 분산인지는 반드시 사람이 확정해야 합니다.

## 기능 분류 체계

`config/function_dict.yaml` 은 일반적인 기업 기능으로 채운 **시드 사전**입니다.
1차 진단 후 회사 실정에 맞게 확정하는 것을 전제로 합니다. 키워드가 넓으면 오탐이 늘어납니다.

한국어 형태소 분석기 없이 동작하도록 규칙 기반 토크나이저 + TF-IDF 코사인 유사도로 구현했습니다.
정밀도를 더 올리려면 `functions.tag_functions()` 를 LLM 기반 태거로 교체하면 됩니다(인터페이스 동일).

## 개인정보 취급

- 사번은 해시 또는 일련번호로 치환해 반입 (이름·연락처 불필요)
- 평가등급·징계 이력 등 민감 정보는 사용하지 않음
- 성별은 개편 판단 근거가 아니라 다양성 현황 참고 지표로만 분리해 사용
- `data/`, `output/` 은 `.gitignore` 로 커밋 차단
